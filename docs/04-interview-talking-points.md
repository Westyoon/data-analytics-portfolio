# Interview Talking Points

## 30초 소개

Python으로 여러 원천 데이터를 수집·정제하고, 결측과 이상값을 품질 규칙으로 관리해 분석과 서비스까지 연결한 경험이 있습니다. 응급의료 프로젝트에서는 서로 다른 기관코드 때문에 병원 데이터가 결합되지 않는 문제를 1:1 매칭과 수동 검증 체계로 해결했고, 검증을 통과한 데이터 세대만 운영에 반영하도록 만들었습니다. 모델링 연구에서는 실험 조건과 metric, checkpoint를 관리하며 결과를 재현하고 비교했습니다.

## 가장 직무와 가까운 문제 해결 사례

**상황:** NEMC와 HIRA가 서로 다른 병원 식별자를 사용해 전문의 데이터를 단순 결합할 수 없었습니다.

**행동:** 병원명뿐 아니라 주소, 전화, 좌표, 시설종별을 비교하고 동일 HIRA 기관이 중복 배정되지 않도록 1:1 매칭했습니다. 낮은 신뢰도의 결과는 강제로 연결하지 않고 후보·미매칭 파일로 분리했으며, 지역 매칭률이 기준 미만이면 전문의 점수를 산출하지 않았습니다.

**결과:** 기준 병원 모집단을 보존하면서 오매칭으로 잘못된 전문의 수가 들어가는 위험을 줄였고, 수동 검토가 필요한 대상을 근거와 함께 전달할 수 있었습니다.

## 데이터 요구사항을 받는다면

1. 사용 목적과 필요한 의사결정을 확인합니다.
2. 행 단위, 기준키, 기간, 필터, 단위와 결과 형식을 정의합니다.
3. 원천 가용성과 `NULL/0` 의미를 합의합니다.
4. 작은 표본을 먼저 제공해 정의를 확인합니다.
5. 전체 추출 후 행 수, 중복, 결측, 합계와 이전 기간 대비 변화를 검증합니다.
6. 컬럼 정의, 추출 기준과 품질 한계를 함께 제공합니다.

## 보완 중인 역량

실제 프로젝트의 ETL은 Python 중심으로 수행했습니다. SQL은 JOIN, CTE, window function, 집계와 데이터 품질 검증 쿼리를 직무 수준으로 빠르게 적용할 수 있도록 보완하고 있습니다. 경험하지 않은 Azure/GCP 운영을 했다고 표현하지 않고, Docker·GitHub Actions·Railway로 구축한 배포와 운영 경험을 Public Cloud 학습의 기반으로 설명합니다.
