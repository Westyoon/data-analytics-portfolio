# 모델 산출물 검증 경험

## Case A. 지역 위험도 모델

### 검증 질문

- 입력 변수는 실제 원천값인가, 이미 가중치가 반영된 점수인가?
- 결측 지역이 학습 데이터에 잘못 포함되지 않았는가?
- 거리 단위가 바뀐 뒤 이전 모델 결과가 혼합되지 않았는가?
- 특정 변수끼리 강하게 중복되어 계수 해석이 왜곡되지 않는가?
- 군집 수는 임의로 정한 것인가, 후보별 지표를 비교했는가?

### 적용한 검증

- 상관관계 행렬과 VIF 산출
- 원천값 기반 선형회귀
- R²·MAE 기록
- 실제값·예측값·잔차를 지역별 결과로 저장
- K-Means 후보 k 평가 결과와 cluster profile 생성
- 산출물 입력 세대와 접근성 계산 기준 일치 여부 확인

검증 스냅샷 기준으로 회귀 결과는 R² 약 `0.8614`, MAE 약 `3.0653`이었습니다. 이 수치는 고정된 성과로 과장하지 않고 입력 데이터 세대가 바뀔 때 함께 재생성해야 하는 운영 산출물로 관리했습니다.

## Case B. 멀티모달 연합학습 실험

### 실험 목적

클라이언트가 가진 이미지·텍스트 모달리티의 정보량이 다를 때 모든 업데이트를 동일하게 사용하는 방식과, 유의미한 클라이언트·모달리티 쌍을 선택하는 방식을 비교했습니다.

### 비교 구조

- 알고리즘: FedAvg, FedProx, FedCola, BMSFed 등
- 학습 범위: `All`, `d_client`, `d_pair`, `m_pair`
- 데이터셋: CIFAR-100, AG News, UPMC Food-101, MM-IMDb 등
- 지표: accuracy, macro-F1, loss, 통신량, 선택 비율
- 스트레스 조건: 이미지 또는 텍스트 모달리티 누락

### 결과 신뢰성 확보 방식

- 데이터셋별 단일·다중 label 차이에 맞춰 loss를 구분
- experiment script로 조건을 명시해 수동 설정 차이 축소
- W&B에 round와 metric step을 연결해 시계열 비교
- server/client checkpoint를 저장해 중단된 장시간 실험 재개
- ablation notebook으로 선택 전략별 결과 비교
- missing modality 조건에서 전체 성능뿐 아니라 모달리티별 head 결과도 확인

### 배운 점

모델 성능 수치 하나보다 **같은 입력, 같은 평가 기준, 같은 실험 조건으로 비교했는지**가 중요했습니다. 이는 실무 모델 산출물을 검증할 때도 feature 세대, 평가 모집단, metric 정의와 재현 가능한 실행 조건을 먼저 확인해야 한다는 원칙으로 이어졌습니다.
